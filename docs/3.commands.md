# Commands

## Run a package manager

After `jup enable`, use npm, pnpm, or Yarn normally:

```sh
pnpm install
yarn add lodash
npm test
```

Without shims, put `jup` first:

```sh
jup pnpm install
```

Run one command with a specific version:

```sh
jup yarn@4.9.0 --version
```

`jup yarn --version` prints Yarn's version. Use `jup --version` for jup's version.

## Set or update the project version

```sh
jup use pnpm@11
```

`use` resolves the request, downloads it, checks it, updates the project pin, and runs the package manager's setup command when needed.

```sh
jup up
```

`up` updates an exact pin within its current major version. For example, pnpm 11 stays on pnpm 11. If `devEngines.packageManager.version` contains a wider range, jup follows that range.

Both commands accept:

- `--here` to edit the current directory's `package.json`.
- `--pin-style=suffix` for the default hash suffix.
- `--pin-style=sidecar` to put the digest in `devEngines.packageManager.integrity`.

See [Project pins](./project-pins) for details.

## Prepare for offline use

```sh
jup install
```

Downloads the version pinned by the current project into the cache. It does not change the pin.

```sh
jup install -g pnpm@11.1.2
```

Downloads a version and records it as the global fallback. Add `--cache-only` to fill the cache without changing the fallback.

```sh
jup pack pnpm@11.1.2
```

Creates a portable archive and records the packed version as the global fallback for projects without a pin. Choose the archive's location with `-o` or `--output`, then import it on another machine:

```sh
jup pack -o package-managers.tgz pnpm@11.1.2
jup install -g package-managers.tgz
```

Read [Cache, offline use, and security](./cache-and-security) for container examples.

## Inspect or clean the cache

```sh
jup cache list
jup cache list --json
jup cache clean
jup cache clean --all
```

`cache clean` removes downloaded versions but keeps recorded global defaults. `--all` removes both. jup prints whether it removed anything and the cache path it used.

## Explain jup's decisions

```sh
jup info
jup info --json
```

`info` does not use the network and does not fail just because the project pin is broken. It reports the problem instead.

Use the text form while troubleshooting. The JSON form has a top-level schema `version` and is suitable for tools. New fields may be added without changing that schema version.

## Enable or disable shims

```sh
jup enable
jup disable
```

Useful options:

```sh
jup enable --exclude npm
jup enable --install-directory "$HOME/bin"
jup enable --force
jup disable --install-directory "$HOME/bin"
```

With no names, these commands handle all supported package manager commands. You can also name only the managers you want.

## Deprecated commands

`prepare` and `hydrate` remain for Corepack compatibility, but jup warns that they are deprecated. Use `pack` and `install -g` for new scripts.

Run `jup --help` for the complete command syntax.
