# Command reference

## Run a tool

```sh
jup <binary>[@<version>] [...args]
```

Examples:

```sh
jup pnpm install
jup yarn@^4 --version
jup node@^22 script.js
```

A shim provides the shorter form (`pnpm install`). A one-command version
override still has to use the package manager required by a strict project.

## `jup use`

```sh
jup use [--here] [--no-integrity] [--no-lockfile] <name[@<version>]>
```

Selects, verifies, and installs a tool, then writes the project pin. A typed
semver range stays in the manifest and its selected release goes into `jup.lock`.
A bare name, tag, or exact version writes an exact pin.

For package managers, `use` may then run the manager's install command. For a
runtime such as Node.js, it only writes `devEngines.runtime`.

- `--here` targets the current directory's manifest.
- `--no-integrity` pins the version alone, and drops any digest already there.
- `--no-lockfile` records no release in `jup.lock`, and drops any entry already
  recorded for the pin. Only a range or tag pin records one.

## `jup up`

```sh
jup up [--here] [--no-integrity] [--no-lockfile]
```

Updates the current project. For a range, it keeps the range and refreshes the
committed resolution in `jup.lock`. For an exact pin, it chooses the newest
release in the same major line unless a structured project range allows another
line. Registry tags are not accepted by `up`.

## `jup pack`

```sh
jup pack [--json] [-o|--output <path>] [...name[@<version>]]
```

Installs the selected versions, makes them global fallbacks on the source
machine, and writes complete store entries to an archive. The default output is
`jup.tgz`. `--json` prints the output path as JSON.

## Cache commands

```sh
jup cache install
jup cache install -g|--global [--cache-only] [...name[@<version>] | <file>.tgz]
jup cache list [--json]
jup cache clean [--all]
jup cache clear [--all]
```

Bare `install` installs the version selected by the current project. It does not
edit the project, committed lockfile, or global fallback.

`install -g` installs named tools or imports portable jup archives. Without
`--cache-only`, each installed tool becomes the fallback outside pinned
projects.

`list` reports installed versions. `clean` and `clear` are aliases. They remove
installed tools; `--all` also removes recorded global defaults. They do not
remove jup's self-install or downloaded signing-key state.

## `jup enable`

```sh
jup enable [--install-directory <path>|--system] \
  [--exclude <name>] [--force] [...name]
```

Creates shims. With no names, it uses the built-in default set. A named tool
expands to all binaries it provides.

- `--install-directory` uses exactly that writable directory.
- `--system` uses the platform's system jup bin directory.
- `--exclude` removes a tool from the default set.
- `--force` backs up and replaces foreign entries.

`--system` and `--install-directory` cannot be combined.

## `jup disable`

```sh
jup disable [--install-directory <path>|--system] \
  [--exclude <name>] [...name]
```

Removes only entries owned by jup and restores anything that `enable --force`
backed up. With no names it considers every supported entry, including optional
shims. It does not remove foreign replacements.

## `jup info`

```sh
jup info [--json]
```

Builds an offline diagnostic report for the project, version resolution, store,
shims, `.npmrc`, TLS, and environment. Credential values are masked. The JSON
format has its own version; readers should ignore fields they do not know.

## Install jup itself

```sh
jup self-install [--install-directory <path>|--system] [--force]
```

Copies the running jup installation to `<JUP_HOME>/self/<version>` and creates
`jup` and `corepack` entries. It does not use the network. The self copy is not
removed by `cache clean`.

```sh
jup self-upgrade [--install-directory <path>|--system] [--force]
```

Downloads and verifies the latest published jup, installs it under `self`, and
updates the same entries. This is different from `up`, which updates the current
project's tool pin.

`JUP_MINIMUM_RELEASE_AGE` does not apply to jup's own release, and an upgrade
never goes backwards: if the registry's newest jup is older than the one running,
it says so and installs nothing.

## Help and version

```sh
jup --help
jup -h
jup help
jup --version
```

`jup --version` prints jup's version. `jup pnpm --version` runs pnpm and prints
pnpm's version.

## Exit and output behavior

- Successful jup commands exit `0`; jup errors exit `1`.
- A proxied tool's exit status or signal is preserved.
- Tool input and output pass through unchanged.
- Management logs and JSON go to stdout.
- Advisories, validation warnings, and download notices go to stderr.
- Proxy usage errors go to stderr. Management usage errors include the command's
  usage line on stdout.

Use `NO_COLOR=1` to disable jup's own color. `FORCE_COLOR` forces it. jup never
adds styling to a proxied tool's output.
