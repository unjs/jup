# Commands

## Run a package manager

After `jup enable`, use familiar commands:

```sh
pnpm install
jup pnpm install       # same route without a shim
jup pnpm@11.22.0 --version
```

A one-command version override must still name the manager required by a strict project. `jup --version` prints the jup version; `jup pnpm --version` prints pnpm's version.

## Choose a project version

```sh
jup use pnpm@11
```

The selector can be a bare name (latest stable), exact version, range, or tag. `use` resolves it to an exact version, verifies and caches the download, writes the pin, prints the changed manifest path, and then runs that manager's install command. Review dependency and lockfile changes as well as `package.json`.

```sh
jup up
```

For an exact pin, `up` stays within the current major unless `devEngines.packageManager.version` supplies another allowed range. For a semver range in `packageManager`, it preserves the range and refreshes only `.jup.lock`. It rejects registry tags; see [Projects and workspaces](./projects-and-workspaces#keep-a-registry-tag-in-packagemanager) to create or deliberately change a retained tag resolution.

Both commands accept:

- `--here`, which uses the current directory's `package.json` as the target. `use --here` may create it; `up --here` requires an existing usable pin;
- `--pin-style=suffix` (default), which appends the digest to `packageManager`;
- `--pin-style=sidecar`, which writes the digest to `devEngines.packageManager.integrity`.

Native aube, Bun, Deno, nub, and Node pins stay digest-free because their artifacts differ by host. Node is pinned in `devEngines.runtime` rather than `packageManager`, and `jup use node@…` writes the pin without running an install command. See [Projects and workspaces](./projects-and-workspaces).

## Prepare for CI or offline use

```sh
jup install
```

Caches the current project's selected version without changing the project pin, `.jup.lock`, or the default used outside pinned projects. For a range or tag, create and commit `.jup.lock` before using this command in frozen CI.

```sh
jup install -g --cache-only pnpm@11.1.2
```

Caches named versions without changing the default used outside pinned projects. This form also imports an archive without activating its contents:

```sh
jup install -g --cache-only tools.tgz
```

Create an archive with:

```sh
jup pack -o tools.tgz pnpm@11.1.2
jup pack --json -o tools.tgz pnpm@11.1.2
```

The default output is `jup.tgz`. `pack` also records packed versions as defaults outside pinned projects on the source machine. Importing with `jup install -g tools.tgz` activates imported versions on the target. Archive import does not authenticate or reverify contents; verify the archive through a trusted transfer, checksum, or signature first. See [CI and offline use](./ci-and-offline).

## Manage defaults and cache

```sh
jup install -g pnpm@11.1.2
```

A **global fallback** is simply the default version jup uses outside a pinned project. This command downloads a release and makes it that default. It can replace a newer default; add `--cache-only` to avoid that side effect.

```sh
jup cache list
jup cache list --json
jup cache clean
jup cache clear       # alias
jup cache clean --all
```

`clean` removes downloaded versions but keeps default-version records. `--all` removes both. Signing-key cache remains.

## Diagnose the current setup

```sh
jup info
jup info --json
```

`info` stays offline and reports invalid settings instead of failing immediately. JSON consumers should ignore fields they do not recognize.

## Install or remove shims

```sh
jup enable
jup disable
```

Bare `enable` creates npm/npx, pnpm/pnpx, Yarn/yarnpkg, and aube/aubr/aubx shims. Bun/bunx, Deno, nub/nubx, and Node are opt-in:

```sh
jup enable bun deno nub node
```

Bare `disable` removes every jup-managed shim, including opt-ins. Both accept `--install-directory`, repeatable/comma-separated `--exclude`, and manager names. `enable --force` deliberately displaces conflicting files; jup records replaced entries for restoration by `disable`. Read conflict and `PATH` warnings before forcing.

Defaults are user-owned: `$XDG_BIN_HOME` when set on non-macOS POSIX, otherwise `~/.local/bin` (including macOS), and `%LOCALAPPDATA%\jup\bin` on Windows.

## Deprecated Corepack commands

`prepare` and `hydrate` still run and print a migration warning each time. Use `pack` instead of `prepare`, and `install -g <archive>` instead of `hydrate` in new automation. All help and usage examples use the name `jup`.
