# Moving from Corepack

Most npm, pnpm, and Yarn projects with an exact `packageManager` pin can switch to jup without changing `package.json`. jup reads Corepack-compatible exact pins and `devEngines.packageManager` declarations.

Before switching, note the jup-only features: aube/Bun/Deno/nub pins, Node pins in `devEngines.runtime`, range or tag pins backed by `.jup.lock`, and sidecar integrity. Corepack can't run projects that use these.

## Important differences

| Area | Corepack | jup |
| --- | --- | --- |
| Project exact pins | npm, pnpm, Yarn | Same, plus aube, Bun, Deno, nub, and Node (in `devEngines.runtime`) |
| Range/tag project pins | Not supported as a repeatable project pin | Supported with a committed `.jup.lock` resolution |
| CLI selectors | Exact/range/tag selectors | Exact/range/tag selectors |
| npm shim | Not enabled by default | Enabled by default |
| Project `.npmrc` | Not used | Constrained registry selection; no project credentials/TLS |
| Manager mirrors, proxies, retries | Limited | Built-in user-facing controls |
| Existing command conflicts | May overwrite shims | Warns/skips foreign files by default and records displaced entries it replaces |
| Cache | Corepack-specific | Separate jup cache and markers |

jup accepts legacy `COREPACK_*` variables, but canonical `JUP_*` values win. Exact digest suffixes stay interoperable.

## Switch one machine

The jup package installs both `jup` and a `corepack` compatibility command. Disabling old Corepack shims doesn't remove that old `corepack` launcher, so inspect and replace it as a separate migration step. If Corepack is your only way to run pnpm for a source build, finish `pnpm install` and `pnpm pack` first. The complete source-build sequence is in [Getting started](./getting-started).

1. Inspect the commands and npm prefix currently in use:

   ```sh
   command -v corepack
   command -v pnpm
   npm prefix -g
   npm ls -g corepack --depth=0
   ```

   In PowerShell, use `Get-Command corepack` and `Get-Command pnpm`.
2. Once the jup archive is ready, remove Corepack's package-manager shims:

   ```sh
   corepack disable
   ```

   This doesn't remove the `corepack` launcher, or shims owned by other version managers.
3. Migrate the launcher based on what you found in step 1:

   - If `npm ls -g` shows a separately installed `corepack` package, run `npm uninstall -g corepack`, then install jup normally.
   - If Corepack came bundled with Node.js, or its ownership is unclear, confirm that the path from `command -v corepack` sits under the global prefix you reviewed, then use npm's forced install as the deliberate replacement step:

     ```sh
     npm install -g --force ./jup-0.0.0.tgz
     ```

   Prefer a plain `npm install -g ./jup-0.0.0.tgz` when there's no launcher conflict. The archive filename may differ.
4. Enable jup:

   ```sh
   jup enable
   ```

   jup includes npm. To preserve Corepack's usual npm behavior:

   ```sh
   jup enable --exclude npm
   ```
5. Verify the result:

   ```sh
   jup info
   command -v pnpm
   pnpm --version
   ```

Read any conflict or `PATH` warning before using `--force`.

## Update automation

| Old workflow | jup workflow |
| --- | --- |
| `corepack install` | `jup install` |
| `corepack install -g ...` | `jup install -g ...` |
| `corepack pack ...` | `jup pack ...` |
| deprecated `prepare` | `jup pack` and, when activation is intended, `jup install -g` |
| deprecated `hydrate archive.tgz` | `jup install -g archive.tgz` |

Add `--cache-only` to `install -g` when seeding must not change defaults outside pinned projects — remember that `jup pack` itself records the packed versions as those defaults. See [CI and offline use](./ci-and-offline).

## Env files, caches, and paths

For each directory, `.jup.env` wins over `.corepack.env`, but discovery still checks closer directories first, so a child `.corepack.env` can beat a parent `.jup.env`. An explicit `JUP_ENV_FILE` or `COREPACK_ENV_FILE` path is used exactly.

jup doesn't automatically migrate Corepack's cache. Warm a new cache with `jup install`, or create a jup archive. Legacy `COREPACK_HOME` is accepted, but sharing an old store doesn't guarantee a format conversion.

Default locations differ:

| Corepack | jup |
| --- | --- |
| `$XDG_CACHE_HOME/node/corepack` | `$XDG_CACHE_HOME/jup` or `~/.cache/jup` |
| `%LOCALAPPDATA%\node\corepack` | `%LOCALAPPDATA%\jup` |
| `corepack.tgz` | `jup.tgz` |
| `.corepack.env` | `.jup.env` |

jup's shim directory is separate: `$XDG_BIN_HOME` when set on non-macOS POSIX, otherwise `~/.local/bin` (including macOS), or `%LOCALAPPDATA%\jup\bin` on Windows.

## Security and manager support

jup can use project digests, registry signatures, or a warned registry digest. It supports scoped `.npmrc` settings, corporate TLS/proxies, and per-manager sources. A valid historical signature under an expired key is accepted with a prominent warning; tampered signatures are rejected. Read [Download verification](./security) before setting policy exceptions.

Native aube, Bun, Deno, nub, and Node caches and archives are host-specific. Their shims aren't all enabled by default: aube is, while Bun, Deno, nub, and Node need `jup enable bun deno nub node`.

## Roll back

```sh
jup disable
npm uninstall -g jup
```

This removes jup-managed shims and restores whatever jup recorded when it replaced them. Reinstall Corepack using its original package or Node.js installation method, then run `corepack enable` for the managers you use. jup leaves the Corepack cache untouched.

If commands still resolve incorrectly, see [Troubleshooting](./troubleshooting) and check the **Shims** section of `jup info`.
