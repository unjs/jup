# Registries and networking

jup uses the public npm registry and each manager's built-in download source by default. You can use an npm-compatible registry, manager-specific mirrors, scoped `.npmrc` credentials, standard proxies, and company certificate authorities.

## Choose the right registry setting

Use `JUP_NPM_REGISTRY` for one npm-compatible registry serving package-manager metadata and downloads:

```sh
JUP_NPM_REGISTRY=https://npm.internal.example/ jup install
```

Use `JUP_REGISTRY_NPM`, `JUP_REGISTRY_PNPM`, `JUP_REGISTRY_YARN`, `JUP_REGISTRY_AUBE`, `JUP_REGISTRY_BUN`, `JUP_REGISTRY_DENO`, or `JUP_REGISTRY_NUB` to mirror only that manager. A per-manager setting rebases the manager's existing source URLs; the mirror must preserve the source's expected paths and protocol.

```sh
JUP_REGISTRY_YARN=https://mirror.internal.example/yarn/ jup yarn --version
```

Registry selection uses this order:

1. the matching `JUP_REGISTRY_<NAME>`;
2. `JUP_NPM_REGISTRY`;
3. an applicable `.npmrc` registry;
4. jup's built-in source.

Run `jup info --json` to see the selected source. A repository `.npmrc` or eligible `.jup.env` setting may redirect downloads, so review routing changes like other dependency configuration.

## Authenticate safely

Use authenticated registries only over HTTPS. For CI, use a masked secret variable:

```sh
JUP_NPM_TOKEN="$TOKEN" jup install
```

For Basic authentication, set both `JUP_NPM_USERNAME` and `JUP_NPM_PASSWORD`. Environment credentials take priority over `.npmrc` credentials and are limited to the configured registry origin. Credentials embedded in a URL take priority for that URL and are removed from displayed errors and cross-origin redirects.

A user `.npmrc` can scope a token to a host and path:

```ini
registry=https://npm.internal.example/
//npm.internal.example/team/:_authToken=${NPM_TOKEN}
```

Host/path scoping limits where jup sends a credential, but it does not require HTTPS by itself; keep the registry URL explicitly `https://`. jup reads registry selection from project, user, and global `.npmrc` files. Only user/global files may supply scoped `_authToken`, `_auth`, or `username` plus base64 `_password`, and TLS settings. Project credentials and TLS settings are ignored with a warning. Never put secrets in repository files or command-line URLs.

## Configure a proxy

Uppercase and lowercase `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, and `NO_PROXY` are supported without extra Node.js flags. Proxy URLs must use `http://` or `https://`. Unsupported schemes such as `socks://` are ignored, which can allow a direct connection; do not rely on them to enforce network isolation.

```sh
HTTPS_PROXY=http://proxy.internal.example:8080 \
NO_PROXY=localhost,.internal.example \
jup install
```

`NO_PROXY=*` bypasses all proxies. Otherwise, comma- or space-separated hosts match that host and subdomains; a leading dot is also accepted, and `:port` limits a match. Proxy URL credentials are supported but can leak through shell history or environment inspection, so prefer your platform's protected secret injection and percent-encode special characters.

## Trust a company certificate authority

Prefer a PEM bundle supplied by your administrator:

```sh
JUP_CAFILE=/etc/company/all-required-roots.pem jup install
```

This **replaces** the platform trust store for jup requests. Include every root needed by the configured registry, mirrors, redirects, and npm key service—not a leaf certificate alone.

The same controls can come from user or global `.npmrc`: `cafile=/path/to/bundle.pem`, inline `ca=...`, and `strict-ssl=false`. Project `.npmrc` TLS entries are ignored. `JUP_CAFILE` takes precedence over `.npmrc`; within `.npmrc`, `cafile` wins over inline `ca`. `JUP_STRICT_SSL` takes precedence over `.npmrc` `strict-ssl`.

For diagnosis only:

```sh
JUP_STRICT_SSL=0 jup install
```

This disables certificate verification and warns when networking uses that setting. A warm cache-only command may not warn because it makes no request. Install the correct CA bundle as the permanent fix.

## Adjust timeout and retries

```sh
JUP_NETWORK_TIMEOUT=60000 JUP_NETWORK_RETRIES=5 jup install
```

The timeout defaults to 30,000 ms. Retries default to three total attempts, including the first; `0` or `1` means one attempt. jup retries safe GET requests after transport errors and HTTP 408, 425, 429, and 5xx responses, honoring `Retry-After`. Other 4xx responses are final.
