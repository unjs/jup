# Registries and networking

> By default, jup uses the public npm registry and each manager's built-in download source.

You can use a different npm-compatible registry or a mirror for one manager. jup also supports `.npmrc` credentials, standard proxies, and company certificate authorities (CAs).

## Choose the right registry setting

Use `JUP_NPM_REGISTRY` for one npm-compatible registry that serves package-manager metadata and downloads:

```sh
JUP_NPM_REGISTRY=https://npm.internal.example/ jup install
```

Use `JUP_REGISTRY_NPM`, `JUP_REGISTRY_PNPM`, `JUP_REGISTRY_YARN`, `JUP_REGISTRY_AUBE`, `JUP_REGISTRY_BUN`, `JUP_REGISTRY_DENO`, or `JUP_REGISTRY_NUB` to mirror only one manager. This replaces the base of that manager's source URLs. The mirror must keep the paths and protocol that the source expects.

```sh
JUP_REGISTRY_YARN=https://mirror.internal.example/yarn/ jup yarn --version
```

Registry selection follows this order:

1. the matching `JUP_REGISTRY_<NAME>`;
2. `JUP_NPM_REGISTRY`;
3. an applicable `.npmrc` registry;
4. jup's built-in source.

Run `jup info --json` to see the selected source. A repository `.npmrc` or eligible `.jup.env` setting can redirect downloads, so review routing changes the same way you'd review any other dependency configuration.

## Authenticate safely

Only use authenticated registries over HTTPS. In CI, use a masked secret variable:

```sh
JUP_NPM_TOKEN="$TOKEN" jup install
```

For Basic authentication, set both `JUP_NPM_USERNAME` and `JUP_NPM_PASSWORD`. Environment credentials take priority over `.npmrc` credentials. jup sends them only to the configured registry origin. Credentials in a URL take priority for that URL. jup removes them from displayed errors and does not send them in redirects to another origin.

A user `.npmrc` can scope a token to a host and path:

```ini
registry=https://npm.internal.example/
//npm.internal.example/team/:_authToken=${NPM_TOKEN}
```

Host and path scoping limits where jup sends a credential, but it does not require HTTPS. Make sure the registry URL starts with `https://`. jup reads registry settings from project, user, and global `.npmrc` files. Only user and global files may provide scoped `_authToken`, `_auth`, or `username` with base64 `_password`. Only those files may provide TLS settings. jup ignores project credentials and TLS settings and prints a warning. Never put secrets in repository files or command-line URLs.

## Configure a proxy

Uppercase and lowercase `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, and `NO_PROXY` are all supported, with no extra Node.js flags needed. Proxy URLs must use `http://` or `https://` — unsupported schemes like `socks://` are ignored, which can let a connection through directly, so don't rely on them to enforce network isolation.

```sh
HTTPS_PROXY=http://proxy.internal.example:8080 \
NO_PROXY=localhost,.internal.example \
jup install
```

`NO_PROXY=*` bypasses all proxies. Otherwise, separate hosts with commas or spaces. Each entry matches that host and its subdomains. A leading dot is also accepted, and `:port` limits the match to one port. Credentials in proxy URLs work, but may appear in shell history or environment inspection. Prefer your platform's protected secret storage, and percent-encode special characters.

## Trust a company certificate authority

Prefer a PEM bundle supplied by your administrator:

```sh
JUP_CAFILE=/etc/company/all-required-roots.pem jup install
```

This **replaces** the platform trust store for jup requests. Include every root certificate needed by the registry, mirrors, redirects, and npm's key service. A leaf certificate alone is not enough.

The same controls can come from user or global `.npmrc`: `cafile=/path/to/bundle.pem`, inline `ca=...`, and `strict-ssl=false`. Project `.npmrc` TLS entries are ignored. `JUP_CAFILE` takes precedence over `.npmrc`; within `.npmrc`, `cafile` wins over inline `ca`. `JUP_STRICT_SSL` takes precedence over `.npmrc`'s `strict-ssl`.

For diagnosis only:

```sh
JUP_STRICT_SSL=0 jup install
```

This disables certificate checks. jup warns whenever a network request uses this setting. A command that only uses a warm cache may not warn because it makes no request. Installing the correct CA bundle is the permanent fix.

## Adjust timeout and retries

```sh
JUP_NETWORK_TIMEOUT=60000 JUP_NETWORK_RETRIES=5 jup install
```

The timeout is 30,000 ms by default. The default retry value means three total attempts, including the first. Values `0` and `1` both mean one attempt with no retry. jup retries safe GET requests after connection errors and HTTP 408, 425, 429, and 5xx responses. It follows `Retry-After`. Other 4xx responses are final.
