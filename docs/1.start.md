# Start

> This guide shows you how to install jup, use it to run package managers, and choose a pnpm version for a project.

## Install

You can install the native binary or use npm.

### Native binary

The native binary is the simplest option. It includes its own runtime, so you do not need Node.js. Builds are available for macOS, Linux, and Windows on x64 and arm64.

::code-group

```sh [macOS and Linux]
curl -fsSL https://jup.unjs.io/install.sh | sh
```

```powershell [Windows]
irm https://jup.unjs.io/install.ps1 | iex
```

::

The installer:

- downloads the build for your system;
- checks it against the release checksum; and
- installs `jup` in the same directory used for its shims.

The default directory is `$XDG_BIN_HOME` or `~/.local/bin` on macOS and Linux. On Windows, it is `%LOCALAPPDATA%\jup\bin`.

On macOS and Linux, the installer prints the line needed to add this directory to `PATH`. On Windows, it updates your user `PATH`. Pass `-NoPathUpdate` on Windows if you only want it to print the command.

To use a different directory, pass its path:

::code-group

```sh [macOS and Linux]
curl -fsSL https://jup.unjs.io/install.sh | sh -s -- --dir "$HOME/bin"
```

```powershell [Windows]
& ([scriptblock]::Create((irm https://jup.unjs.io/install.ps1))) -Dir "$HOME\bin"
```

::

Run the install command again to upgrade. To uninstall, run `jup disable`, then delete the binary.

::warning
`jup enable` does not work from the native binary yet. Its shims point at a small launcher file that only the npm package installs, and a single-file binary has nothing for them to point at. Everything else behaves the same, including `jup pnpm install`, `jup use pnpm@12`, `jup info`, and `jup disable`. Install from npm if you want the `npm`, `pnpm`, and `yarn` commands themselves to pass through jup.
::

### npm

Use npm if your project installs tools with npm or pins their versions in `package.json`.

You need:

- Node.js 22.18 or newer; and
- a writable global npm directory that is on `PATH`.

Install jup globally:

::pm-install{name="-g jup"}
::

jup provides a compatible `corepack` command. If npm says that `corepack` already exists, find the existing command and check how Corepack was installed:

```sh
command -v corepack
npm prefix -g
npm ls -g corepack --depth=0
```

In PowerShell, replace `command -v corepack` with `Get-Command corepack`.

If `npm ls -g` lists `corepack`, remove that global package before installing jup again:

```sh
corepack disable
npm uninstall -g corepack
npm install -g jup
```

If Corepack came with Node.js, compare its path with the global npm prefix shown above. Check that npm will replace the correct file. Then run:

```sh
corepack disable
npm install -g --force jup
```

Use `--force` only after checking the file it will replace. You should not need administrator or root access when the global npm directory belongs to your user.

To return to Corepack, uninstall jup:

```sh
npm uninstall -g jup
```

Then reinstall Corepack in the same way you installed it before, or repair the Node.js installation that included it. Run `corepack enable pnpm` afterward.

Confirm that jup is available:

```sh
jup --version
```

## Enable the shims

This step needs the npm install. Run:

```sh
jup enable
```

This creates small launcher files called **shims** for `npm`, `npx`, `pnpm`, `pnpx`, `yarn`, `yarnpkg`, `aube`, `aubr`, and `aubx`. A shim lets jup check the current project before it starts the package manager.

jup also supports Bun, Deno, nub, and Node, but does **not** create their shims by default. These commands can run files directly and usually come from a separate installation. aube only works on projects, so its shims are created by default. To add the optional shims, name them:

```sh
jup enable bun deno nub node
```

This adds `bun`, `bunx`, `deno`, `nub`, `nubx`, and `node`. A later `jup disable` with no arguments removes them along with everything else.

::warning
`jup enable node` puts jup's `node` ahead of your existing installation for every project on the machine. Enable it deliberately, and only if you want project-pinned Node everywhere. You can always run a pinned Node without a shim: `jup node@22 script.js`.
::

By default, jup puts shims in a directory owned by your user. It uses `$XDG_BIN_HOME` when set on non-macOS POSIX systems, `~/.local/bin` on other POSIX systems (including macOS), and `%LOCALAPPDATA%\jup\bin` on Windows. If the directory isn't on `PATH`, jup prints the line to add to your shell configuration. Open a new terminal after changing `PATH`. In an existing POSIX shell, you may also need:

```sh
hash -r
```

To install the shims somewhere else, give it a directory that's already on `PATH`:

```sh
jup enable --install-directory "$HOME/bin"
```

For a machine-wide install — a container image, a shared build machine — use `--system`, which writes to `/usr/local/bin` (`%ProgramData%\jup\bin` on Windows) and needs permission to do so:

```sh
sudo jup enable --system
```

`--system` never falls back to a user-owned directory: if it can't write there, it fails and says so. Use `jup disable --system` to remove those shims again. As root, a bare `jup enable` also reaches `/usr/local/bin` when no user-owned directory is on `PATH`, which is the usual case inside a container; it prints the directory it chose.

npm is included by default, which lets strict mode reject `npm install` when a project declares pnpm or Yarn. To leave your existing npm command untouched, exclude it:

```sh
jup enable --exclude npm
```

If jup reports a conflict, inspect the named path first:

```sh
command -v pnpm
jup info
```

jup leaves foreign command files alone by default. Use `--force` only when you deliberately want it to replace them:

```sh
jup enable --force
```

When jup displaces a command, it records what it replaced so `jup disable` can restore it later.

## Pin a package manager

Change to the project you want to configure, then run:

```sh
jup use pnpm@12
```

jup finds the newest pnpm 12 release, downloads and verifies it, then writes the exact version to `package.json`:

```json
{
  "packageManager": "pnpm@12.1.2"
}
```

pnpm 12 and later ships a separate binary for each operating system and architecture, so the pin carries no digest — one taken here would fail on a colleague's machine. jup verifies each system's own download against the registry's signature instead. A manager with a single file for every system, such as npm or Yarn, is pinned with a digest suffix. See [Projects](./projects#pin-a-manager-with-per-system-builds).

`use` then runs the selected manager's install command. It may change dependencies or lockfiles. Review the changes and commit the ones you want, including the manifest.

## Run pnpm normally

With the shims enabled, use the command you already know:

```sh
pnpm install
```

Without shims, invoke the package manager through jup:

```sh
jup pnpm install
```

You can override the **version** for one command, but not the manager named by a strict project pin:

```sh
jup pnpm@12.22.0 --version
```

To switch this project from pnpm to Yarn, change its pin with `jup use yarn@<version>`.

## Check the result

Run the offline diagnostic report:

```sh
jup info
```

Use `jup info --json` for automation or a support attachment. Both forms stay offline, and both report every invalid project setting instead of stopping at the first one.

Check these sections:

- **Project** shows the manifest and pin jup found.
- **Resolution** shows the selected package manager version.
- **Store** shows whether that version is already cached.
- **Shims** shows where the launcher commands are installed and whether another command wins on `PATH`.
