# Environment variables

Start with `jup info`: it shows the effective project, paths, registry, and network policy, and tells you whether credentials are present without revealing their values. Use the `JUP_*` names below when you need to override a setting. Legacy `COREPACK_*` twins are accepted too, at lower precedence. Lookup order is process `JUP_*`, then process `COREPACK_*`, then the closest eligible env-file value, then the default. Presence wins — even an empty `JUP_*` value shadows its `COREPACK_*` twin.

POSIX examples use `NAME=value command`. In PowerShell, use `$env:NAME='value'`; in cmd.exe, use `set NAME=value && command`.

## Project and version selection

| Variable | Values/default | What it does | In `.jup.env`? |
| --- | --- | --- | --- |
| `JUP_ENABLE_PROJECT_SPEC` | `1` (default), `0` | Set `0` to ignore project declarations. | Yes |
| `JUP_ENABLE_STRICT` | `1`, `0` | Set `0` to allow another manager; it uses that manager's default outside pinned projects, not the project's version. | Yes |
| `JUP_ENABLE_AUTO_PIN` | `0`, `1` | Add a pin when a project has none. | Yes |
| `JUP_ENABLE_PRERELEASES` | `0`, `1` | Include prereleases during automatic selection. | Yes |
| `JUP_FROZEN_LOCKFILE` | `1`, other | `1` blocks `.jup.lock` creation/refresh. CI freezes normal commands by default; an explicit `jup up` is still allowed unless this is explicitly `1`. Any other explicit value thaws normal CI use. | Yes |
| `JUP_MINIMUM_RELEASE_AGE` | non-negative hours | Exclude younger releases from automatic selection; fractions work. Exact/cached versions are unaffected. Invalid values, and sources with no usable date, fail closed. | Yes |
| `JUP_SPEC_FILE` | path from starting directory | Use this file instead of manifest discovery. Missing files error; ignored when project specs are disabled. | No |

## Cache, paths, and execution

| Variable | Values/default | What it does | In `.jup.env`? |
| --- | --- | --- | --- |
| `JUP_HOME` | path | Stores managers, defaults, keys, and shim restoration records. Default: `$XDG_CACHE_HOME/jup` or `~/.cache/jup`; Windows `%LOCALAPPDATA%\jup`. A repository env file can choose this trusted executable state, so override it in the process for untrusted work. | Yes |
| `JUP_SHIM_DIRECTORY` | path | Default `enable`/`disable` location. `$XDG_BIN_HOME` when set on non-macOS POSIX, otherwise `~/.local/bin` (including macOS); Windows `%LOCALAPPDATA%\jup\bin`. | Yes |
| `JUP_DEFAULT_TO_LATEST` | `1`, `0` | Set `0` to use the built-in default instead of looking up latest stable. | Yes |
| `JUP_ENV_FILE` | filename/path, or `0` | Selects an env file, or disables env files. Only takes effect from the process environment. | No |
| `JUP_NODE_EXECPATH` | reserved | Accepted as a compatibility name but not currently used to select a runtime. The current jup distribution itself requires Node.js 22.18 or newer to start. | Yes |

## Registry and authentication

| Variable | What it does | In `.jup.env`? |
| --- | --- | --- |
| `JUP_NPM_REGISTRY` | Select an npm-compatible registry. | Yes |
| `JUP_REGISTRY_NPM`, `JUP_REGISTRY_PNPM`, `JUP_REGISTRY_YARN` | Rebase that manager's own source to a compatible mirror. | Yes |
| `JUP_REGISTRY_AUBE`, `JUP_REGISTRY_BUN`, `JUP_REGISTRY_DENO`, `JUP_REGISTRY_NUB` | Rebase that native manager's source to a compatible mirror. | Yes |
| `JUP_NPM_TOKEN` | Bearer token scoped to the configured registry origin. | No |
| `JUP_NPM_USERNAME`, `JUP_NPM_PASSWORD` | Basic credentials; both are required. | No |

See [Registries and networking](./registries-and-networking) for precedence and `.npmrc` scoping.

## Network and TLS

| Variable | Values/default | What it does | In `.jup.env`? |
| --- | --- | --- | --- |
| `JUP_ENABLE_NETWORK` | `1`, `0` | Set `0` to block jup's network requests. It doesn't block the executed manager's own dependency network. | Yes |
| `JUP_NETWORK_TIMEOUT` | ms; `30000` | Connection and idle timeout. | Yes |
| `JUP_NETWORK_RETRIES` | total attempts; `3` | Includes the first attempt; `0` and `1` both mean no retry. | Yes |
| `JUP_CAFILE` | PEM path | Replace the platform trust store for jup requests. | No |
| `JUP_STRICT_SSL` | `1`, `0` | Set `0` to disable TLS verification and warn when used. | No |

Upper/lowercase `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, and `NO_PROXY` are also supported. Only HTTP and HTTPS proxy URLs are used; an unsupported scheme can result in a direct connection instead.

## Verification, downloads, and output

| Variable | Values/default | What it does | In `.jup.env`? |
| --- | --- | --- | --- |
| `JUP_ENABLE_DOWNLOAD_PROMPT` | `0` via `jup`, `1` via shim | Controls the download notice/question. Confirmation also requires a TTY and no `CI`; `0` suppresses both. | No |
| `JUP_REQUIRE_SIGNATURES` | `0`, `1` | Refuse the registry-digest fallback. A project digest still takes precedence. | Yes |
| `JUP_ALLOW_UNVERIFIED` | `0`, `1` | Allow an artifact with no usable verification, and warn. | No |
| `JUP_INTEGRITY_KEYS` | JSON, `0`, or empty | Replace trusted registry keys; `0`/empty disables registry verification. | No |
| `JUP_ENABLE_UNSAFE_CUSTOM_URLS` | `0`, `1` | Allow known managers to use custom URLs. | No |
| `JUP_QUIET_ADVISORIES` | `0`, `1` | Suppress only jup-added advisory lines, not errors or inherited warnings. | No |
| `DEBUG` | `jup` or `corepack` | Enable debug output from the process environment. | No |

Read [Download verification](./security) before weakening any trust setting.

## Env files

jup loads the closest `.jup.env`, or `.corepack.env` in the same directory when `.jup.env` is absent:

```dotenv
JUP_ENABLE_STRICT=0
JUP_NETWORK_TIMEOUT=60000
JUP_REQUIRE_SIGNATURES=1
```

`JUP_ENV_FILE` selects another filename/path, or `0` to disable env files; it can't itself come from an env file. An explicit path is used exactly and doesn't fall back to `.corepack.env`. Ineligible settings are ignored. Security-sensitive entries — credentials, trust/TLS controls, unsafe URLs, spec overrides, advisory muting — produce a warning; selection-only entries such as `JUP_ENV_FILE` and the download-prompt setting can be ignored silently.

## Variables jup sets

jup passes `JUP_ROOT` (and `COREPACK_ROOT`) to identify its installation, and `JUP_MIGRATE_FROM` (plus its twin) during applicable setup/migration. `JUP_NODE_EXECPATH` remains reserved for compatibility and isn't currently an effective runtime selector.

Use `jup info` or `jup info --json` to inspect effective values. Credential values are never shown.
