# Getting started

This guide installs jup, routes package manager commands through it, and pins a pnpm release in a project. The same steps work with npm and Yarn.

## Requirements

You need:

- Node.js 22.18 or newer;
- Git;
- pnpm, either installed as a standalone command or temporarily made available through Corepack; and
- a user-writable npm global installation directory on `PATH`.

jup is not published to npm yet, so the current version must be built from source.

## Install from source

Clone and build with an existing standalone pnpm command:

```sh
git clone https://github.com/unjs/jup.git
cd jup
pnpm install
pnpm pack
```

If pnpm is available only through Corepack, keep it available until the archive has been built:

```sh
git clone https://github.com/unjs/jup.git
cd jup
corepack enable pnpm
pnpm install
pnpm pack
```

The filename printed by `pnpm pack` comes from the version in `package.json`; `jup-0.0.0.tgz` below is only an example.

Before installing the archive, inspect the existing Corepack launcher and npm's global packages:

```sh
command -v corepack
npm prefix -g
npm ls -g corepack --depth=0
```

In PowerShell, use `Get-Command corepack` instead of `command -v corepack`. Then remove the old manager shims:

```sh
corepack disable
```

`corepack disable` does **not** remove the `corepack` launcher itself. The jup package also installs that command for compatibility, so finish the migration in one of these ways:

- If `npm ls -g` shows a separately installed `corepack` package, run `npm uninstall -g corepack`, then `npm install -g ./jup-0.0.0.tgz`.
- If Corepack came with Node.js, or its ownership is unclear, compare `command -v corepack` with the global prefix you just printed. After reviewing that path, deliberately replace the launcher with:

  ```sh
  npm install -g --force ./jup-0.0.0.tgz
  ```

Do not use `--force` until you have checked which file it will replace. Administrator or root access should not be necessary when npm's global prefix is configured for your user. If a normal install works without replacing another launcher, prefer it.

To roll back, run `npm uninstall -g jup`, reinstall Corepack using its original installation method (or repair the Node.js installation that supplied it), then run `corepack enable pnpm`. The archive you packed remains available if you need to reinstall jup.

Confirm that the command is available:

```sh
jup --version
```

After jup is released to npm, the source build can be replaced with:

```sh
npm install -g jup
```

Do not use that command until an official release is announced.

## Enable the shims

Run:

```sh
jup enable
```

This creates commands for `npm`, `npx`, `pnpm`, `pnpx`, `yarn`, `yarnpkg`, `aube`, `aubr`, and `aubx`. These small launcher files are called **shims**. They let jup inspect the current project before starting the package manager.

Bun, Deno, nub, and Node are supported but are **not** shimmed by default, because each of those names also runs a file you hand it, and usually belongs to an installation you chose yourself. (aube only ever acts on a project, so it is shimmed by default like the rest.) Ask for them by name:

```sh
jup enable bun deno nub node
```

This adds `bun`, `bunx`, `deno`, `nub`, `nubx`, and `node`. A later `jup disable` with no arguments removes them along with everything else.

::warning
`jup enable node` puts jup's `node` ahead of your existing installation for every project on the machine. Enable it deliberately, and only if you want project-pinned Node everywhere. You can always run a pinned Node without a shim: `jup node@22 script.js`.
::

jup installs shims in a user-owned directory by default: `$XDG_BIN_HOME` when set on non-macOS POSIX systems, otherwise `~/.local/bin` (including macOS), or `%LOCALAPPDATA%\jup\bin` on Windows. If that directory is not on `PATH`, the command prints the line you need to add to your shell configuration. Open a new terminal after changing `PATH`. In an existing POSIX shell, you may also need:

```sh
hash -r
```

To install the shims somewhere else, provide a directory already on `PATH`:

```sh
jup enable --install-directory "$HOME/bin"
```

npm is included by default. This allows strict mode to reject `npm install` when a project declares pnpm or Yarn. To keep your existing npm command unchanged, exclude it:

```sh
jup enable --exclude npm
```

If jup reports a conflict, inspect the named path first:

```sh
command -v pnpm
jup info
```

Foreign command files are normally left alone. Use `--force` only when you deliberately want jup to replace them:

```sh
jup enable --force
```

When jup displaces a command, it records it so that `jup disable` can restore it later.

## Pin a package manager

Change to the project you want to configure, then run:

```sh
jup use pnpm@11
```

jup finds the newest matching pnpm 11 release, downloads and verifies it, and writes the exact version to `package.json`. The result looks like this (digest shortened for the example):

```json
{
  "packageManager": "pnpm@11.1.2+sha512.abc123..."
}
```

`use` then runs the selected manager's install command. Expect ordinary install output and possible dependency or lockfile changes. Review and commit all intended changes, including the manifest.

## Run pnpm normally

With the shims enabled, use the command you already know:

```sh
pnpm install
```

Without shims, invoke the package manager through jup:

```sh
jup pnpm install
```

You can override the **version** for one command, but not the manager named by a strict project pin:

```sh
jup pnpm@11.22.0 --version
```

To switch this project from pnpm to Yarn, change its pin with `jup use yarn@<version>`.

## Check the result

Run the offline diagnostic report:

```sh
jup info
```

Use `jup info --json` for automation or a support attachment. Both forms stay offline, and they report invalid project settings instead of failing at the first one.

Check these sections:

- **Project** shows the manifest and pin jup found.
- **Resolution** shows the selected package manager version.
- **Store** shows whether that version is already cached.
- **Shims** shows where the launcher commands are installed and whether another command appears first on `PATH`.
